**How pushes work here:** never push without Scott's go-ahead, however small
or verified the change. He reviews in code by default and calls for the dev
server himself when he wants it. Don't back out or remove work without asking
either: "it didn't fix X" is not "it should go".

## 0. Getting started (every session)

1. Repo: `~/Desktop/the-lost-trailhead`. `git switch main && git pull --ff-only`;
   `npm install` if `package.json` changed.
2. Start the dev server in the background: `npm run dev` (http://localhost:5173,
   hot-reloads). Confirm it answers 200 and tell Scott it's up. For phone
   testing use `npm run dev -- --host`, and **warn Scott first** (macOS may show
   a firewall prompt).
3. `cd scripts/flyover-check && npm install` once.
4. Work on a branch; when Scott says push: commit, PR, merge, then verify the
   live site (https://the-lost-trailhead.vercel.app) serves the change.

**Distance rule (Scott, 09-25; also in the flyover-check README):** the page
shows WTA's roundtrip distance. Compare it with the track (smoothed climb x 2
for an out-and-back, smoothed total for a loop). Within 10%: use WTA. More
than 10% off: our route differed, so adjust with Scott's confirmation. Always
compare the up and down legs first: Mailbox went up the old trail and down
the new one, and Mt. Si Winter's descent differed too. `gpxcheck.py` ignores
`TRAIL_START` trims (Blanca reads long there).

**Rules Scott set while tuning:**
- Don't change a live hike's behavior unless asked. When a fix would touch
  other hikes, make it opt-in per hike (`LINE_GRADE_LIMIT`, `FORCE_LOOP`,
  `TURN_AT_HIGH_POINT` and so on) unless he says site-wide.
- Don't cut or "correct" the recorded route to match an assumption. Red Top's
  side trip past the lookout stays in.
- No added complexity or performance cost unless it fixes something visible.
  Tile stitching was tried and dropped for that reason (see the roadmap).
- Scott runs whole-flight scans himself when he wants to; keep side checks to
  a line.

## 3. Method notes

- **Verify from rendered pixels,** not computed positions. A computed check said
  "aligned" twice while the render was off (#44, and Blanca on 09-25).
- The headless probes that worked are in the session scratchpad, not the repo:
  patch `terrainFlyover.js` in flight via Playwright `page.route` to expose
  `window.__fly`, then read `lineGround`, `cameraPoints`, billboard positions,
  and `globe.pick` rays for occlusion.
- After re-uploading a GPX, delete the old copy from `scripts/flyover-check/.cache`
  (grep the `.bin` and `.gpx` files for its date) before rescanning.
- One GPU-heavy run at a time on the iMac.
