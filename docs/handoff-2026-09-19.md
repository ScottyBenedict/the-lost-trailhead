## 1. Range map on the About page — SHIPPED (PR #41), desktop only

Live on `/about`. Vector water (`src/data/water.json`), state lines drawn
over the map as polylines, flat 2D Mercator so the 49th parallel is level
and eastern Washington is vertical. Rebuild the data with
`scripts/flyover-check/fetchwater.py` then `fetchborders.py`, and check it
with `watercheck.py` (30 landmarks, offline, no browser).

**It is switched off below 700px.** Cesium is not even fetched there — see
`MIN_MAP_WIDTH` in `src/components/RangeMap.jsx`. Scrolling the About page
on an iPhone exhausted the tab and Safari reloaded it; capping the relief
tiles and handling `webglcontextlost` were not enough.

**The fix, when someone picks this up:** the map is a fixed, north-up,
non-interactive picture, so it does not need a 3D engine on any device.
Generate the relief once as a committed image and place the pins as
absolutely-positioned HTML by a Mercator transform. That works on phones,
drops a 663 kB chunk, makes the pins real tappable elements, and renders
identically every load. Everything needed to produce the image already
exists in `scripts/flyover-check/`.

Known cosmetic issue: a dozen hikes cluster around Snoqualmie Pass and
their pins overlap. Pins scale down below 700px (`PIN_PX` in
`src/lib/rangeMap.js`) but that only helps so much.

available resolution. If the only snow-free option is lower resolution (or
there isn't one), **discuss with Scott before switching**.

**Snow in the current imagery** (`snowcheck.py`): Hidden Lake 17.9% avg / 37.7%

3.6 / 32.3, Manastash 2.9 / 18.9. All other hikes ~0.

**Option:** Esri's Wayback archive (196 releases since 2014; CORS-enabled). The
current imagery for Valhalla is a 2025-03-01 WorldView-3 capture at **0.31 m**

which serves a 2015-07-02 WorldView-2 capture at **0.5 m** — lower source
resolution, so this is a discuss-first case. At the flyover's 900 m camera range
each screen pixel covers ~1–2 m of ground, so the difference may not be visible.

## Photo weight and the Supabase outage (2026-09-19, PR #40)

Supabase restricted the project for exceeding the free plan's 5 GB monthly
CDN allowance and the live site lost bios, photos and trip data. Nothing had
ever been resized: 133 photos averaging 4 MB, a 2.5 MB avatar in a 180px
circle, ~28 MB per hike page. **Most of the traffic was ours** — localhost
pulls from the same CDN, and every `scan.mjs` / `card.mjs` / `range.mjs` run
loads a real hike page.

Now: photos resize in the browser on upload (WebP, 2880px, plus an 800px
`thumb_<name>` beside each one, found by convention with no DB column), the
buckets enforce 3 MB / 1 MB / 8 MB server-side whatever the client, and the
browser checks cache to `.cache/http`. `public/photos` went 220.8 MB → 52 MB;
Storage went 540 MB → 190 MB. A pre-migration backup of all 165 objects is at
`~/Desktop/tlt-storage-backup`, byte-verified — safe to delete once you are
happy.

The project is on Pro ($25/mo) to restore service. Egress is roughly 30x
lower now, so Free should be comfortable again — watch one billing cycle
before dropping back.
